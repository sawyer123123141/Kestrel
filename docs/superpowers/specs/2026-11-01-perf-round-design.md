# The performance round (design, 2026-11-01)

**Status: design.** The controller's goal (from `docs/superpowers/plans/2026-11-01-frontier-roadmap-proposal.md`, section 3 and step 2): every measured case within 1.3x of Rust `--release`, by KIR and codegen fixes only, with determinism untouched. This supersedes parts 1 and 2 of the draft `docs/superpowers/specs/2026-10-26-list-costs-design.md` (its parts 3-5 stay open). Plan: `docs/superpowers/plans/2026-11-01-perf-round.md`.

## Why

Each case still more than 1.3x behind Rust has a named cause in a results file, and none of the causes needs a second backend. Two were confirmed for this design by disassembling the saved exes in `kestrel/bench/2a` (built 2026-10-11, so their loop layout predates `loop_exits.rs`, but the code generator's choice for each statement below is unchanged since): Rust's collatz loop (`rs_collatz.exe`) is `test r11b,1; sar r10,1; lea rsi,[r10+r10*2]; inc rsi; cmovne r10,rsi`, branch-free, while Kestrel's (`kr_collatz.exe`) is the seven-instruction bias chain `sar 63; shr 63; lea; and -2; sub; test; je` and a branch on the parity, which the predictor can't learn; and Rust's `fib` (`rs_fib.exe`) is a loop with one recursive call (`acc += fib(n - 1); n -= 2`), while Kestrel makes both calls. `kr_loop.exe` has an `idiv` for `% 1000000007`, and `kr_heightmap.exe` 64 of them.

## Non-goals

- LLVM or any second backend; the decision on it is taken after this round's numbers (roadmap section 3).
- Autovectorising (SLP or loop). `vec4`/`ivec4` stay the way to SIMD.
- Any syntax, keyword, built-in, library name or Cargo dependency.
- The draft list-costs parts 3-5 (widening runs of bounds checks, `clear` without zeroing, lists in a struct), demanded bits, a float `/ 2^k` as a multiply (measured to change nothing, `kernels/results.md:438`), frameless leaf functions, devirtualising.

## Anti-goals

- **Any bit change in a deterministic program.** Every rewrite is exact by construction: integer arithmetic that gives the same bits for every input, selects between values computed exactly as the branches compute them, and orderings that are unique. No float operation is reassociated, contracted (FMA), reordered or replaced. Pong's saved 600-frame and desync outputs, the runtime's results hash `0xF8962BD9040E8F6C`, and every `@prove(deterministic)` program's output stay byte-identical in JIT, checked exe and `--release` exe.
- **A checked build slower**, or any build slower beyond noise on a case this round doesn't target.
- **A failing program that says something else:** the same panic, message, line and index, and the same output before it. `kestrel check --report` keeps its text; its counts may only go down.
- A stale list header: a list grown, cleared, replaced, or reached through another name inside a loop read from an old copy.
- Compile time of `voxel/main.kes` and `bench/voxels3d/main.kes` up by more than 5%.

## The design

**1. Division and remainder by a constant** (`codegen/src/func/divide.rs`). Today 0, -1, 1 and `±` powers of two are special and every other literal is a bare `sdiv`/`srem`, which Cranelift never moves out of a loop (it can trap), so heightmap's `i % 7` runs per block in the y loop. New: for `i64` and `i32`, every literal `d` with `|d| >= 3` that isn't a power of two uses the signed magic number of Hacker's Delight 10-1 (`M`, `s` for the type width `W`): `t = smulhi(n, M)`; `t += n` when `d > 0` and `M < 0`; `t -= n` when `d < 0` and `M > 0`; `t = t >> s` (arithmetic); `q = t + (t >>> (W - 1))`; and `r = n - q * d` (wrapping). `d = -2^k` is `-(n / 2^k)` (never overflows for `k >= 1`), with `n % -2^k == n % 2^k`; `d = MIN` gives `q = (n == MIN)` and `r = n == MIN ? 0 : n`. `u8` is widened to `i32`. All are pure instructions, so Cranelift hoists invariant ones. The existing bias chain for signed `% 2^k` stays (`sign = n >> (W-1)`; `bias = sign >>> (W-k)`; `r = n - (((n + bias) >> k) << k)`), and two compare shapes skip it: `n % 2^k == 0` and `n % 2^k != 0` become `n & (2^k - 1) == 0` / `!= 0`, exact for every signed `n` (a truncated remainder is zero exactly when `2^k` divides `n`). Expected: loop 1.0-1.1x, collatz's test one `test`, heightmap's `% 7` out of the y loop. Risk: the magic constants; mitigated by exhaustive tests against Rust's `wrapping_div`/`wrapping_rem`. Determinism: integer results equal for every input.

**2. Small branches as selects, and the exact shift** (`codegen/src/func/stmt.rs` `if_stmt`, the value `if` in `expr.rs`, new `select.rs`). An `if` becomes straight-line code when its condition and both branches have no check left after range marking, no call, no store to memory, no load but of register locals, no division but by a constant, at most 3 operations per branch, at most 2 register locals assigned, and no nested `if` (start values; the builder may tighten them so that no measured kernel gets slower). Both sides are computed in written order, then each local is `select(cond, then, else)` (an unassigned side keeps the old value): Cranelift `select` (`cmov`) for integers and bools, `wide_pick.rs`'s compare-and-blend for floats (Cranelift's float `select` is a jump). Separately, inside the then side of `n % 2^k == 0` (or `n & (2^k-1) == 0`) on a register local `n` not assigned earlier in that side, `n / 2^k` is `sshr n, k`, exact because `n` is a multiple of `2^k`; this holds whether the `if` stays a branch or becomes a select. Expected: collatz becomes Rust's loop (1.0-1.3x), swarm's bounce stops mispredicting. Risk: a well-predicted branch made a select costs a little; the size limits and the step kernels' timings decide. Determinism: the selected value is bit-identical to what the branch computes; nothing speculated can trap or print.

**3. List headers in SSA across a loop** (new `codegen/src/func/headers.rs`, hooks in `place.rs` `element_addr`/`bounds_check`, `collections.rs` `len`/`list_add`, `stmt.rs` loop lowering; the spike `hdr_cache.rs` in `.superpowers/sdd/list-spike-partial.patch` is one working shape). At a loop's entry, a list place `P` that the loop can't change has its `{data, len}` loaded once into Cranelift variables, and inside the loop `P[i]`, `P.len` and a `for ... in P` element pointer use them. A list the loop only reads and `add`s to also keeps `cap`; `add` updates the variables, stores the new length to memory at every `add` (write-through), and on the grow path calls the runtime and reloads `data` and `cap`. **The aliasing rule.** `P` is a local `R` with field steps only (no index, map, variant, payload or lane step), of list or array type. A header is 24 bytes `{data, len, cap}` in its owner's memory (a stack slot, a parameter's memory, or the buffer of an outer list when lists nest), never in `P`'s own buffer, so a store to an element of `P` (or of any list) never changes `P`'s header. Only these can, and any of them in the loop (its condition, body, nested loops, and statements inside expressions) stops `P` being cached: (a) a statement whose target is `P`, a prefix of `P`, or `P` extended by fields: `Assign`, `ListAdd` (allowed for an add-cached `P` only), `List` (clear, insert, remove, sort's runtime call is harmless but counted), `SetLen`, `Dup`, `CopyItems` into it, `MapSet`; (b) a `Let`, `Bind`, `BindEnv` or `BindGlobal` of `R`, or a `Bind` of `R` itself inside the loop when `R` is a loop element; (c) a call with an `Arg::Ref` rooted at a local whose home (`promote.rs` `home`) is `R`'s home, unless that place leaves `P`'s path at a different field of a struct or passes through an index step of `P` first (a callee given `P[i]` gets an element pointer and can't reach the header); (d) any `CallIndirect`, `CallVirtual`, `ParFor`, `MakeFn`, `MakeIface`, `CopyFnEnv` or `CopyIface` (a closure or interface value could hold `R`). Reads of `P`'s header by anything else in the loop (a read-only call argument, a copy of `P`) read memory, which is current because `data` and `cap` change only through the reload and `len` is written through. More than 3 add-cached lists in one loop caches none of them (the spike's `KSPIKE_ADDMAX`, to be set from measurement). Cranelift memory flags (alias regions) were rejected: every store that may write header bytes would need the header region, and a raw copy of an enum or optional overlays headers and numbers in one store, so no single region is right. Also here: `map`'s generated loop reserves `xs.len` items before it starts (`ListOp::Reserve`, `kir/src/lower/list_fns.rs`), so its `add` never grows; and `copy_fields` (`place.rs`) copies a plain struct of 4-byte leaves whose size is a multiple of 8 in 8-byte integer moves without the `aligned` flag (a bit copy). Expected: copy 1.2-1.6x, map 1.1-1.4x, filter 1.0-1.05x, swarm and the race as in Goals. Risk: a stale header, the memory-safety anti-goal; every case in (a)-(d) gets a program test that tries to break it. Determinism: the same values, read once.

**4. Promoting `parts[i]`** (new `kir/src/bind_index.rs`, run in `optimize` before `promote`; `promote.rs`). After inlining, `parts[i].step(...)` is a run of places `parts[i].pos`, `parts[i].vel` in memory, each re-indexed. In a run of statements where every place rooted at list `R` is `R[i]...` with one index expression `i` that is a local not written in the run, `R`'s header can't change by decision 3's rule, and no other route reaches `R`'s elements, the pass inserts `Bind(e, R[i])` before the statement holding the first access and rewrites the places to `e...`; `promote` then keeps `e`'s fields in registers as it does for a `for ... in` element. The `Bind` carries the first access's index check and line, and is placed only where that access is the first thing in its statement that can fail or has an effect, so a failing index names the same line and index as today. Range analysis proves the `Bind`'s index as it proves `parts[i]` today. Also in `promote.rs`: a loop element whose region only reads whole plain-struct values to store them elsewhere (`positions[i] = p.pos`) isn't promoted, so codegen copies it with decision 3's 8-byte moves instead of loading and storing each leaf. Expected: `step_index.kes` at `step.kes`'s speed. Risk: evaluation order; the bounds-failure tests pin it. Determinism: the same float operations on the same values.

**5. Plain enums in registers** (`kir/src/scalarize.rs`, `leaves.rs`, `split.rs`). `block_at(y, h).weight()` makes a `Block` in a stack slot and matches on it (`heightmap/results.md:55`). An enum local whose every variant has only plain fields, which no address is taken of (no `Arg::Ref`, `Bind`, interface or closure), which is only assigned `VariantLit`s or another split enum local, and only read by `Tag` and variant-field places or copied to another split enum local, is split into a tag local and one local per (variant, leaf). An assignment of a value `if` or `match` whose arms end in variant literals is first pushed into the arms. Because such a local is never stored to or loaded from memory whole, no reader of enum bytes (`checksum`, `to_bytes`, `==`, `first_difference`) can see the inactive variant's leaves. Expected: with decision 1, heightmap 1.3-1.6x. Risk: low; the split is the struct split with a tag. Determinism: values only.

**6. Accumulator recursion as a loop** (new `kir/src/recurse.rs`, run on the build's copy after range marking, `--release` only). A function whose final value is `if c { base } else { E }`, where `E` is `f(a) op f(b)` or `f(a) op x` with `op` one of `+ * ^ & |` on integers (wrapping in `--release`, so associative and commutative), becomes `acc = identity; loop { if c { return acc op base } acc = acc op f(a); <params> = b }` (for fib: `acc += fib(n - 1); n -= 2`, which is `rs_fib.exe`'s loop). Calls keep their order (`f(a)` runs before `b` is evaluated) and every expression keeps its guarding condition, so the range marks stay valid. Checked builds keep the recursion (their overflow points would move). One level of self-inlining was rejected: twice the code for less than half the calls removed. Expected: fib 1.1-1.4x, one call per two levels, the frame cost left. Risk: a wrong `base` combination; exhaustive small-`n` tests. Determinism: wrapping integer `+ * ^ & |` are associative and commutative, so every bit is equal.

**7. Loop-invariant checks before the loop** (new `kir/src/hoist_checks.rs`, run after range marking; `kir/src/range/loops.rs`). 14 checks per sample remain in the frozen world (`voxels3d/results.md:116`). A check whose operands the loop never writes moves, with its value (into a new local, as `hoist.rs` does for math), to the loop's entry, guarded by "the loop runs at least once", when everything that runs before it in the iteration has no observable effect (no print, write, file or native call) and no check that can fail, so the same panic with the same line comes first. Checks keep their written order, and each goes to the outermost loop it is invariant in (`cx * 32` before the chunk, `cx * 32 + x` before the y loop). Memory writes before the check don't count: a panic ends the process, and the Godot add-on throws the memory away. Separately, range analysis learns one rule: a counter set to a constant `c` before a nest of `for` loops with constant trip counts `n1 ... nk` and no `break`, `continue` or `return`, bumped by 1 once per innermost iteration at its top level and written nowhere else, is below `c + n1 * ... * nk`; that proves `out[i]` and `i + 1` (`out.len` is 34 cubed). Expected: no check per sample, checked over `--release` 1.15x to at most 1.03x. Risk: an effect missed before the check; tests with a print before a failing invariant check. Determinism: the same values.

**8. Sort with keys computed once** (`kir/src/lower/sort.rs`, `runtime/src/sort.rs`, `codegen/src/rt.rs`, `jit.rs`). `sort_by` with a number or bool key: the generated function fills a scratch buffer with each item's key in a loop where the key literal is inlined (today the runtime calls the key through a pointer per item), then calls a new runtime `kestrel_rt_sort_keyed_int`/`_float(items, len, size, keys)`. The runtime maps each key to order-preserving `u64` bits (`i64`: flip the sign bit; `f64`: `-0.0` as `0.0`, every NaN as `u64::MAX`, then flip the sign bit or all bits), sorts `(bits, position)` pairs with a stable LSD radix sort (11-bit digits, a digit every key shares skipped; insertion sort below 64 items), and moves each item once into an uninitialised scratch buffer and back (no zeroed `vec!`). `sort()` on a list of numbers takes the same path with the item as its key. Sorting `(key, index)` then one permutation pass was picked over moving items with their keys because a radix pass would move every item every pass. Expected: 0.7-1.1x Rust. Risk: the float order; tests with NaN, `-0.0`, infinities, equal keys. Determinism: a stable sort by a total preorder has exactly one result, so any correct algorithm gives the same bytes.

**9. Xor, and, or chains reassociated** (new `kir/src/reassoc.rs`, after range marking). Cranelift 0.137 dropped the rebalancing that combined the frozen world's invariant hash parts (`voxels3d/results.md:316`). In a chain of one of `^ & |` on integers inside a loop, the operands the loop never writes are grouped into one subexpression the loop hoists (`x*A ^ y*B ^ z*C ^ s*D` in the x loop becomes `x*A ^ (y*B ^ z*C ^ s*D)`). `+` and `*` are left alone (checked builds' overflow points). Expected: frozen world 1.13x to 1.0-1.08x (the tuned copy, 0.92x, shows the ceiling). Determinism: these operators are associative and commutative on every bit.

## Constraints

- Builds and benchmarks only when the PC is free (never while the user games). Light test mode per task; the exe pass and the full suite once, in the last task.
- Files under about 400 lines; messages and comments plain sentences. Never a visible window; never a bare `link.exe`.
- Passes after range marking (6, 7, 9) run in `codegen/src/lib.rs` `define_module` on the analysed copy through one KIR entry, `kir::after_marking(m, arith)`, so `kestrel check --report` and contracts are untouched.

## Tests

- One program test per decision with exact `// expect:` output, and failure tests where a decision moves a check (decisions 3, 4, 7): the same `// expect-stderr:` line and index as before. Decision 1: a codegen test comparing every new path through the JIT with Rust's `wrapping_div`/`wrapping_rem` over edge values and 100,000 seeded dividends for each of about 60 divisors (`±3 .. ±13`, `1000003`, `1000000007`, `65537`, `MIN`, `MAX`, `-2^k`), `i32` and `i64`. Decision 3: a test per case (a)-(d). Decision 8: the runtime's existing `matches_the_standard_library_on_random_items` extended to the keyed path.
- Machine-code tests in `codegen/tests` that count what each fix removes (no `idiv` in `loop`, a `select` in collatz, no header load inside the copy loop, no `explicit_slot` in heightmap's checksum, one `call` per iteration in fib, no `trap user` in the voxel sample block, checked).
- Determinism: the results hash test, Pong's reference outputs (`pong_demo.rs`), the `det_*` and rollback programs in JIT, checked exe and `--release` exe; `kestrel check --report` byte-identical for the frozen world, `voxel/main.kes` and every `bench/kernels/*.kes` except counts going down.
