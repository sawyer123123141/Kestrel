# The rollback library and modules in folders (design, 2026-10-31)

Builder check 2026-11-01 (`.superpowers/sdd/2026-10-31-rollback-library/spec-builder-check.md`): items 1-9 verified on the release compiler; its changes are folded in.

Roadmap step 4 (`2026-10-29-roadmap-proposal.md`), from the proposal `docs/superpowers/plans/2026-10-30-rollback-library-proposal.md`. The controller ruled on its three questions while the user was away (the user may rename anything later): Part A is a built-in module in plain Kestrel, like `random`; Part B makes dotted names folders; the names are the proposal's. Where this spec departs from the proposal, the decision says so and why ("Departs:").

## Why

Pong's rollback netcode (`demos/pong/peer.kes`, `net.kes`, `replay.kes`, about 400 lines) is the part of a networked game nobody wants to write twice: a snapshot ring, input histories, a guess for the other player, rollback and re-simulation on a wrong guess, confirmed frames, checksums, a desync report, a replay. Today it is demo code. As a library, any deterministic Kestrel game gets it by implementing one interface. Separately, a module today is one file next to its user; a project of any size wants folders.

## Goals

- G1. `use rollback` works in every program (JIT and built exes, no path, no install); a game implements `Rollback` and drives a `Session` with five calls a frame.
- G2. Pong is rewritten on the library and keeps its headless output byte for byte; it keeps only its game, drawing, bots and the demo wiring.
- G3. The library's own tests cover a lost packet, a long stall, a desync, a deep rollback and a replay, with a tiny game, so it is tested apart from Pong.
- G4. `use net.packet` loads `net/packet.kes` relative to the using file; full names work in type positions (closing "`geom.Point` doesn't work in a type position yet").
- G5. Every existing program, test and message is unchanged except where a decision names the change.

## Non-goals

- More than two players (the same shape with an index per player; a follow-up).
- Real networking (round 3's UDP natives); acknowledgements and resending (a packet carries the last 8 inputs, as Pong's does).
- A game-defined input type (interfaces have no placeholders).
- Packages, a search path, `..` in names, re-exporting a module's items from another module.
- Follow-up 76 (a gameplay edit during a rollback): deferred, decision 9.

## Anti-goals

- `advance` allocating for a game whose state is plain data (numbers, vectors, structs, an `Rng`): it must prove `no_alloc` through a one-line wrapper in the game.
- A session that grows memory as it runs. Recording a replay is opt-in and lives in the game's own `Replay`.
- A dotted name that can mean two files without an error, or one file loaded twice under two names.

## The design (decisions)

**Part A: the `rollback` module**

1. **A built-in module of four files** (`kestrel/driver/std/rollback.kes` and `std/rollback/{session,replay,fakenet}.kes`, each under 400 lines; peer.kes alone is 258). Departs: the proposal allowed one file; generic and documented it is about 550 lines. The embedding table becomes `MODULES: [(&str, &[(&str, &str)])]`: a module's name and its parts, each a path under `<builtin>/` and its source (`("draw", &[("draw.kes", ...)])`, `("rollback", &[("rollback.kes", ...), ("rollback/session.kes", ...), ...])`). The loader parses each part as its own `Source` (so diagnostics and runtime errors name `rollback/session.kes` and its line) and merges the parts' programs into one `Module` named `rollback` before linking: items, `proves` and `hex_literals` concatenated, `expr_count`/`bind_count` the last part's (the largest), identical `use` clauses kept once. The parts see each other's items as one file's. `rollback` uses `random` (for `FakeNet`'s `Rng`) and needs no window library (`needs_window` is unchanged). The Godot add-on refuses every built-in module today (`random` too), so `rollback` too; unchanged here. A user file `rollback.kes` beside a program that writes `use rollback` gets today's "`rollback` is a built-in module, so rollback.kes can't be used as a module; rename the file" (no such file exists in the repo).

2. **`Input` is fixed:** `pub struct Input { buttons: int = 0, x: float = 0, y: float = 0 }`, 12 bytes; `Input()` is no button held. Departs: the proposal wrote `buttons: u32`; Kestrel has no `u32` (only `int`, `i64`, `u8`), so it is a 32-bit `int` used as 32 bits (`buttons & 2`, `1 << 31` included). The library compares two `Input`s field by field (Kestrel has no `==` on structs): a NaN axis never matches, so it rolls back every frame, and `-0.0` matches `0.0`; both are documented and harmless for a `step` that doesn't tell them apart.

3. **The interface:** `pub interface Rollback { pure step(var self, one: Input, two: Input) }`, the whole simulation for one frame. Departs: the proposal wrote `step(var self, mine: Input, theirs: Input)`; the two peers would then pass the inputs in opposite orders and their states could never agree. `one` is player 1's input and `two` player 2's, on both peers. `Session[G: Rollback]` calls `self.game.step(one, two)`, which in each compiled copy is a direct call to the game's method (generics: a call through a rule is direct unless `G` is an interface type). A game must be `pure`; it states its contracts on the method itself: `@prove(deterministic, no_alloc) pure step(var self, one: Input, two: Input) { ... }`, and implements the interface as `struct Game: Rollback` (after `use { Rollback from rollback }`) or `struct Game: rollback.Rollback` (decision 15). `G` may be an interface type by the generics rules (an interface meets its own rule), but a session of one fails at `checksum` inside `rollback/session.kes` ("`checksum` can't take an interface value"), help "in the copy `rollback.Session[...]`". This is accepted: a game is a concrete struct, and an error test pins the message.

4. **Constants** (in `rollback.kes`, `pub`): `RING = 16` snapshots, so a rollback goes at most 16 frames back; `HIST = 64` frames of inputs kept; `MAX_AHEAD = 12`: a session that is 12 or more frames past the other player's newest known input waits a frame; `SUM_EVERY = 30` frames between checksums; `SENT = 8` inputs per packet; `MAX_DELAY = 8`; `REPLAY_SUM_EVERY = 60`. These are Pong's numbers, so Pong's output stays the same. Kept checksums: 8 of each side (private `SUMS`).

5. **`Packet`** is plain data, sent with `to_bytes` over anything: `pub struct Packet { sender: int, frame: int, inputs: [Input], sum_frame: int, sum: i64 }`: the sender's player (1 or 2), the frame of its newest input, its inputs for `frame - 7 .. frame` (`inputs[SENT - 1]` is `frame`'s; frames before 0 are `Input()`), and its newest checksum and that checksum's frame (0 before the first).

6. **`Session[G: Rollback]`** (`rollback/session.kes`). Fields (all readable, as every Kestrel field is; written only by the methods): `me: int`, `delay: int`; `game: G`, the present (the state at the start of frame `now`); `now: int`; `ring: list[G]` (`ring[f % RING]` is the state at the start of frame `f`; a `list` built with `add`, since generic code can't use `array[G](n)`); `local_in`, `remote_in`, `guess: [Input]` and `remote_at: [int]` (`HIST` each; a field can't share a method's name); `known: int` (the other player's inputs are known for every frame before it); `last: Input`, `last_at: int` (the newest input received and its frame, -1 before the first); `wrong: int` (the first frame run on a wrong guess); `checked: int`; `sum_frame: int`, `sum: i64`; `mine`, `theirs: [i64]` and `mine_at`, `theirs_at: [int]` (`SUMS` each); `compared: int`; `desync_at: int` (-1), `desync_mine`, `desync_theirs: i64`, `reported: bool`; `rollbacks`, `deepest`, `waits: int`. Departs: the present state is the field `game`, not a `game()` method, so drawing a large state reads it in place instead of copying it.
   - `pub pure new_session[G: Rollback](start: G, me: int, delay: int) -> Session[G]`: every ring slot holds `start`, `remote_at` is -1 everywhere. `me` is 2 for the second player and 1 for anything else; `delay` is clamped to `0 .. MAX_DELAY`. (Kestrel has no way yet for a library to stop a program with a sentence; an `exit`/`fail` built-in is a follow-up, so the rule is documented in the module's comment instead.) Written `new_session(new_game(SEED), me: 1, delay: 2)` or `new_session[Game](...)`.
   - `pure local(var self, i: Input)`: this player's input, for frame `now + delay` (`delay` frames of input delay hide that many frames of latency, so fewer rollbacks). A second call in one frame replaces the first; a frame with no call after a frame that ran gets `Input()` (`advance` clears the next slot after it runs a frame; after a wait the slot keeps the waited frame's input). The first `delay` frames are `Input()` on both peers.
   - `pure remote(var self, p: Packet)`: a packet from the other player, in any order, duplicates included; one whose `sender` is `me` is ignored. Each input for a frame not known yet and less than `HIST` past `known` is stored; a frame already run on a guess that differs marks `wrong = min(wrong, f)`; `known` moves past every frame now known; the newest input by frame becomes the guess; the packet's checksum is kept at `(sum_frame / SUM_EVERY) % SUMS`. It never rolls back by itself, so many packets in one frame cost one rollback.
   - `pure catch_up(var self)`: when `wrong < now`, counts a rollback (`rollbacks += 1`, `deepest = max(deepest, now - wrong)`), restores `ring[wrong % RING]` and runs the frames again up to the present with the inputs now known; then `wrong` is none. `advance` does this first; a game calls it before `local` when its input reads the present state (Pong's bots), so the input comes from the corrected state. Departs: the proposal had only `advance`; without this Pong's bots would read the uncorrected state and Pong's output would change.
   - `pure advance(var self)`, step by step: (1) `catch_up()`. (2) When `now - known >= MAX_AHEAD`, wait: `waits += 1`, nothing runs, and this frame's `local` input is replaced by the next one. Otherwise run frame `now`: `ring[now % RING] = game` (storage-reusing; a plain state copies without allocating), the inputs are this player's `local_in[now % HIST]` and the other's real input when `remote_at` holds frame `now`, else the guess (`last`, or `Input()` before any), stored in `guess`; they go to `step` in player order; `now += 1`; the slot for frame `now + delay` is cleared to `Input()`. (3) Confirm: frame `c = min(known, now)` is final on both peers; each newly confirmed `f` with `f % SUM_EVERY == 0` has its state's checksum taken in place (`checksum(game)` or `checksum(ring[f % RING])` in the two branches of an `if`, never `checksum(if ... { game } else { ... })`, which copies) into `mine` and as the `sum`/`sum_frame` to send. (4) Compare, while `desync_at < 0`: each next checksum frame both sides have, in order: equal moves `compared` on; different sets `desync_at`, `desync_mine`, `desync_theirs` and stops comparing. `@prove(deterministic)` is written on `local`, `remote`, `catch_up` and `advance` (checked on every copy; it holds whenever `step` is `pure`).
   - `pure outgoing(self) -> Packet`: a new packet (its 8-input array is allocated in the current arena: call it inside an `arena { }` or send it at once): `sender: me`, `frame: now - 1 + delay` (the newest frame whose input is final), its 8 inputs, `sum_frame`, `sum`.
   - `pure confirmed(self) -> int`: `min(known, now)`.
   - `desync(var self) -> string?`: once, after the first difference: `desync at frame 330: my checksum <a>, theirs <b>` (the `i64`s as `print` writes them; departs: the proposal's `0x...`, since there is no hex formatting); `none` before and after. `desync_at` is there for a program that only needs the frame. Kestrel has no `if let`, so the module comment and the README show `let why = s.session.desync() else { return }` in a helper, not the proposal's `if let`.
   - `pure run_again(var self, f: int)`: restores frame `f`'s snapshot and runs to the present (what `catch_up` uses). For tests and demos that change a confirmed snapshot on purpose (Pong's `DESYNC_AT`).
   - `pure record(self, var r: Replay[G])`: adds every frame confirmed since the last call (both players' inputs, and every `REPLAY_SUM_EVERY` frames the checksum of the state once that frame ran). Call it once a frame after `advance`; a frame whose state has left the ring ends the replay there (nothing more is added). Departs: the proposal had `Session.replay() -> Replay`; a session that kept every frame would allocate in `advance` and grow forever for games that never record.

7. **`Replay` and `check_replay`** (`rollback/replay.kes`): `pub struct Replay[G: Rollback] { start: G, inputs: list[Input], sums: list[i64] }` with frame `f`'s inputs at `2f` (player 1) and `2f + 1`; `pure frames(self) -> int`; `pub pure new_replay[G: Rollback](start: G) -> Replay[G]`; `pub pure check_replay[G: Rollback](r: Replay[G]) -> int` runs the inputs from a copy of `r.start` and gives the first frame whose checksum differs, or -1. Departs: the proposal had `check_replay[G](start: G, r: Replay)` with a seed in the replay; the library knows no seeds, a start state need not come from one, and a replay that carries its start can't be checked against the wrong one. `to_bytes(r)` and `from_bytes[Replay[Game]](b)` save and load it. `pub pure difference[G: Rollback](a: Session[G], b: Session[G]) -> string?`: for two sessions in one process, `first_difference` of their states at the older of their confirmed frames, as `at frame 330: ball.x: 401.5 and 401.501`; `none` when equal or when that frame has left either ring.

8. **`FakeNet`** (`rollback/fakenet.kes`), Pong's `Net` made general: `pub pure new_fake_net(seed: int, latency: int, jitter: int, loss: float) -> FakeNet`; `pure send(var self, now: int, p: Packet)` (one `randf()` for the loss, then `randi_range(0, jitter)`, exactly Pong's draws; 32 slots; a full set loses the packet); `pure deliver(var self, now: int) -> list[Packet]` (a new list: call it inside an `arena { }`); fields `sent`, `lost`. `send` copies the packet into a free slot field by field and input by input, never by assigning the `Packet`, so a packet made in a frame's arena can be sent to a `FakeNet` outside it (the escape check refuses a whole-value store).

9. **Hot reload and follow-up 76.** Nothing in the hot reload host changes; `Session[G]` and `FakeNet` hold no interface or function value, so they may sit in a reloadable `State`. Follow-up 76 is **deferred**: the host swaps code between frames without telling the program, so a library cannot see the swap; on two machines each reloads alone, and agreeing on a swap frame is a protocol message, which belongs with real networking. In one process an edit to `step` may desync the peers, and the session then reports it, which is the honest outcome. The follow-up's text gains this sentence.

10. **Pong on the library.** Pong becomes `pong.kes` and `game.kes`; `peer.kes`, `net.kes` and `replay.kes` are deleted. `game.kes`: `Game` (unchanged fields, so its checksums are unchanged) implements `Rollback`; `step` becomes the method `@prove(deterministic, no_alloc) pure step(var self, one: Input, two: Input)` decoding `UP = 1`, `DOWN = 2` into the existing `Pad` and `move_pad`; `bot` gives an `Input`; `Inputs` and `same` go. `pong.kes`: `PongState { p1, p2: Session[Game], net: FakeNet, replay: Replay[Game], nudged: bool, ...today's scalars }`; each network frame: `deliver` (in an arena) and `remote` by sender; `catch_up` both; each bot reads its own session's `game`; `local` and `advance` p1 then p2; when `DESYNC_AT >= 0` and p2's `checked` has reached it, the nudge of today's `peer.confirm` (`game.ball.x` when it is the present, else `ring[DESYNC_AT % RING].ball.x` and `run_again`); `p1.record(var s.replay)` when `RECORD` (a new `let RECORD = true`); `outgoing` p1 then p2, sent in an arena; `differ = max(p1.desync_at, p2.desync_at)`. Pong proves its frame allocation-free with `@prove(deterministic, no_alloc) pure advance_peer(var p: Session[Game]) { p.advance() }` (the library writes no `no_alloc`: it is checked on every copy and would fail for a game whose state holds a list). `check_file` reads `from_bytes[Replay[Game]]` and calls `check_replay`. The printed lines, frame counts, `rollbacks`, `deepest`, `lost`, `checksums compared up to`, `peers differ at frame 330` and `replay differs at frame 360` stay exactly as today. The nudge moves from inside `peer.confirm`'s per-frame loop to after the batch; that is equal because one `advance` never confirms 30 frames at once (the lag is at most `MAX_AHEAD` plus jitter), and a comment by the nudge says so. The flat-memory test sets `RECORD = false` in both runs, so it measures the sessions and the network, which must stay flat; the replay's growth (24 bytes a frame and 8 every 60 frames, against 4 a frame today) is the documented cost of recording.

11. **`pong.replay` changes format, deliberately.** It is `to_bytes` of the library's `Replay[Game]`: the header, the start `Game` (40 bytes: two `vec2`, two `float`, two `int`, the `Rng`'s `i64`) in place of the `int` seed, then `2F` `Input`s of 12 bytes and the sums. Keeping the old layout would need Pong's own replay type beside the library's; the format is a demo's, nothing outside the repo reads it, and an old file is refused with Pong's existing "`<path>` is not a Pong replay; pass a file that a run of Pong wrote, like pong.replay" (the fingerprint differs). The demo tests' offsets change with it (`INPUTS_AT = 13 + 40 + 4`, 24 bytes a frame; the inputs' length at bytes 53..57 is `2F`; the size is `INPUTS_AT + 24F + 4 + 8(F / 60)`; frame 300's player 1 buttons at `INPUTS_AT + 24 * 300`, whose first byte is checked `<= 3` before bit 0, `UP`, is flipped).

**Part B: modules in folders**

12. **Dotted names.** A module name in `use` is names joined by dots: `use net.packet`, `use { Packet from net.packet }`, and in braces. In the using file's folder `D`, `use a.b` loads `D/a/b.kes`, else `D/a/b/b.kes` (the folder's own file); `use net` loads `D/net.kes`, else `D/net/net.kes`, so a module can grow into a folder without changing its users. When both exist: "`net` could be net.kes or net/net.kes; remove or rename one of them". Missing: today's "can't find module `geom`: there's no `geom.kes` next to this file" for a single name with no folder; "can't find module `net`: the folder net/ has no net.kes; add one, or use a module inside it, like `use net.packet`"; "can't find module `net.packet`: there's no net/packet.kes next to this file". Names never go up (no `..`), so every file is the entry's folder or below it; from `net/x.kes`, a missing `use game` adds the help "a module finds modules next to it or in folders below it, never above". A single name that is a built-in module is the built-in, as today; a dotted name never is, and one starting with a built-in's name is refused: "`draw` is a built-in module, so a folder can't be called draw; rename the folder".

13. **One file, one module, one full name.** A file is loaded once, keyed by its canonical path, or by its joined path made lexically normal when it isn't on disk (an editor buffer, a test's in-memory file); today it is keyed by name. Its `Source.path`, and so every compile diagnostic, stays the joined path as today (never Windows' `\\?\` form). On a case-insensitive disk `use Net.packet` and `use net.packet` are one file, and its full name is spelled as first loaded. The loader records which module each `use` clause resolved to and hands that to `link`, which stops looking modules up by written name (the written name only decides the short and first-name bindings); the missing-module messages move from `link` to the loader, which reads every candidate path through `read` so hot reload notices a candidate created later. Its **full name** is its path from the entry file's folder, `/` as `.`, without `.kes`, and `x/x.kes` is `x`: `net/packet.kes` is `net.packet` whether the entry wrote `use net.packet` or `net/net.kes` wrote `use packet`. Linked names are the full name and the item (`net.packet.Packet`); a flat program's names are today's (`geom.Point`). Two files can only get one full name through decision 12's "could be" case, which is an error.

14. **Names in code.** After `use net.packet`, its items are reached by the last name (`packet.make()`, `packet.Packet(...)`) or the full name (`net.packet.make()`); `use { Packet from net.packet }` brings `Packet`. The first name of a full name a file uses is taken in that file: a local or item `net` gets today's "`net` is already defined: it's imported; pick another name" / "`net` is already defined here". Two whole-module uses with one last name bind neither short name: `packet.x` is then "`packet` could be `net.packet` or `ui.packet`; write the full name, like `net.packet.Packet`", and the full names work. When one of them is a single name (`use draw`, `use packet`), that name keeps the short name, since it is its full name, and the dotted one is reached by its full name only (`ui.draw.x`). A file using both `net` and `net.packet` whose `net.kes` has a `pub` item `packet` gets, at the second `use`: "`net.packet` is both the module net/packet.kes and `packet` in net.kes; rename one of them". `print` still shows the bare type name.

15. **Full names in type positions.** The type parser accepts `a.b.T` and `a.b.T[int]` (one `Named` type whose name has dots); the linker resolves the prefix as a module the file uses (short or full) and rewrites it to the linked name, so `geom.Point`, `net.packet.Packet` and `geom.Stack[int]` work in every type position. The same dotted names work in a struct's or enum's interface list and in a placeholder's rules (`struct Game: rollback.Rollback`, `[G: net.packet.Shape]`), which the grammar parses apart from types. An unknown prefix: "`geo` isn't a module this file uses; add `use geo`, or import the type: `use { Point from geo }`". The "Imports and visibility" bullet "`geom.Point` doesn't work in a type position yet" and the generics "Not built" item go.

16. **Messages that name files.** Compile diagnostics keep the full path, as today. Runtime errors name the file by its path from the entry's folder with `/` (`on line 24 of net/packet.kes`), which for a file beside the entry is today's base name; a built-in part is named from `<builtin>/` (`rollback/session.kes`; `draw.kes` as today). "it's in main.kes, which `net.packet` can't see" uses the full name. Contract chains and `kestrel check --report` name other files the same way (`it allocates on rollback/session.kes:88`), and the report's plain function names drop the module's full name (`Session[Game].advance`): the KIR module carries each file's module full name (`module_names`) beside `files`, instead of deriving it from the file name.

17. **The language server** matches a `use` clause to its file by the module's full name (a `module` field on each `Source`; for a built-in of several parts, the first part), not by the file stem; go to definition works on `packet` in `packet.make()` and on each part of `net.packet.Packet` in a type; built-in parts are written under its builtin folder with their subfolder (`builtin/rollback/session.kes`) and `is_builtin_copy` accepts that folder and below. A module file opened alone is analysed as its own entry, as today, so its uses resolve from its folder. Hot reload needs nothing: `Compiled.files` holds every loaded file, folders included.

## Constraints

- No new syntax beyond dotted `use` names and dotted type names (decisions 12 and 15); no new keywords, built-in functions or Cargo dependencies.
- Error messages are plain sentences that say what to do. Files under about 400 lines.
- Nothing in the hot reload host changes; Pong stays a `setup`/`frame` program.
- Every existing program test, error test and demo test keeps its output, except Pong's replay-file offsets (decision 11), its memory test's `RECORD = false` (decision 10) and the module list in `builtin.rs`'s and `modules.rs`'s tests.
- Never a visible window in tests (`KESTREL_HEADLESS`, `KESTREL_HIDDEN`).

## Tests

- **Part B** (`cli/tests/module_folders.rs`, projects with subfolders in scratch dirs): `use net.packet` by short name, full name and `use { .. from }`; full names in parameter, field, `let`, `list[...]`, optional and generic (`geom.Stack[int]`) positions, and `geom.Point` in a flat program; `net/net.kes` loaded by `use net` and using `packet` beside it; one file reached by two names is one module (a `var` global bumped through both prints 2); each message of decisions 12, 14 and 15; a runtime error in `net/packet.kes` names `net/packet.kes`; `kestrel build` of a folder program prints what `run` prints; a reload test (`cli/tests/reload.rs`) editing `net/packet.kes` prints `reloaded`. LSP unit tests: definition on a dotted `use`, a dotted type and a built-in part.
- **Program tests** (`tests/programs/`, each with exact `// expect:` lines, using a tiny `Tally: Rollback` whose state is a few ints and an `Rng`): `rollback_basic.kes` (two sessions over a perfect hand-carried wire, equal checksums, `compared` up to the last checksum frame); `rollback_delay.kes` (delay 2: inputs land 2 frames later, fewer rollbacks than delay 0); `rollback_deep.kes` (the other's inputs held back 8 frames then changed: `deepest` 8, final checksum equal to a run given the inputs on time); `rollback_lost.kes` (`FakeNet` with 30% loss converges, `lost > 0`; a hand-dropped run of 5 packets is recovered by the 8-input redundancy); `rollback_wait.kes` (no packets for 20 frames: `now - known` stops at 12, `waits` counts, then it resumes); `rollback_desync.kes` (peer 2 starts one field off: `desync()` once at frame 30, then `none`; `difference` names the field); `rollback_replay.kes` (record, `to_bytes`/`from_bytes[Replay[Tally]]`, `check_replay` -1; one input changed gives the next checksum frame); `rollback_list_state.kes` (a state holding a `list[int]` works and rolls back correctly).
