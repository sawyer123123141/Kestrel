# The language round: `exit` and `fail`, `Result` and `try`, interface placeholders, inferred `pure`, packages (design, 2026-11-01)

From `docs/superpowers/plans/2026-11-01-language-proposals.md`. The user took all five picks and ruled packages as imports with a lock and no manifest; the controller set the build order: `exit`/`fail`, then `Result` with `try` and `else why`, then interface placeholders, then inferred `pure`, then packages. Where this spec departs from the proposals, the decision says so and why ("Departs:"). Names are the user's and are listed at the end. This spec amends `2026-10-09-kestrel-syntax-design.md`; the last task writes the amendments into it.

## Why

Kestrel's demos hit the same five gaps: a library can't refuse a bad argument (`new_session` clamps, follow-up 83) and a program can't set its exit code (Pong's replay check exits 0, follow-up 58); a failure is `none` with its reason somewhere else (`file.error()`, the voxel engine's `load_failure` guessing afterwards); the rollback library fixes a 12-byte `Input` for every game (follow-up 96: Pong's replay grew from 4 to 24 bytes a frame); a helper without `pure` stops a distant `par for`, so `pure` is written on three of every four functions; and shared code is copied between programs.

## Goals

- G1. `exit(code)` sets a program's exit code; `fail("sentence")` stops it with the sentence and its line (exit 101), also from `pure` code. Recordings keep the code, and `kestrel replay` compares it.
- G2. `Result[T, E]` is built in; `try r` passes an error up in one word; `let x = r else why { }` names it. `file` and `from_bytes` give `Result[..., string]` with the reason, and `file.error()` and `load_failure` go.
- G3. Interfaces take placeholders: `interface Rollback[I]`, `struct Game: Rollback[Pad]`, `[G: Rollback[I], I: equatable]`; `equatable` covers plain structs and enums, and `==` works on them. Pong runs on its own 2-byte input with byte-identical output.
- G4. `pure` is inferred for every function with a body; a written `pure` is a checked promise; the `par for` error names the chain to the effect.
- G5. Packages' syntax and lock format are fixed here (built in their own round).
- G6. Every existing program prints what it printed, except the outputs this spec names.

## Non-goals

- Catching a `fail`, or keeping the hot-reload window open after one (a later follow-up, as in the hot reload spec).
- Error conversion between error types (Rust's `From`), a `must use` rule for a dropped `Result`, methods on `Result` (`is_ok`, `unwrap_or`), a type for "nothing" (Rust's `()`).
- Associated types, placeholders on methods (interface or struct), overloading, more than two rollback players (follow-up 82).
- Inferring `pure` into function types; removing written `pure` from the demos.
- Building packages (decision 33).

## Anti-goals

- A `Result` or a `try` in a hot loop that costs more than the tag compare, branch and payload move the hand-written `match` costs.
- An error message that names a symptom without saying what to write instead.
- An inference that changes what any program prints, or that makes a library's purity change silently for its users (decision 32).
- `exit` ending the Godot editor's process.

## The design (decisions)

### A. `exit(code)` and `fail(message)` (task 1-2)

1. **Two global built-ins that never return.** `exit(code: int)` and `fail(message: string)` join `Builtin::GLOBAL_NAMES`, so both names are reserved ("`fail` is a built-in name; pick another"; no `.kes` file in the repo uses either). Their type is `never` (`Ty::Never`), as `return`'s, so a call ends a block: an `else` block (`let hp = scores[name] else { fail("no score for {name}") }`), an `if` branch used as a value (`let n = if ok { 3 } else { fail("not ok") }`), the end of a value-returning function. A wrong argument says what to pass: "`exit` takes an `int` exit code, found float", "`fail` takes the message as a string, found int".
2. **`fail`** goes through the runtime's `panic::fail`, as every runtime error does: it flushes printed output, finishes a `--record` file with the failure as its last entry, hands the message to the Godot failure hook, keeps `par for`'s lowest-index rule, and prints `kestrel: <message> on line <L>` with the file named as runtime errors name it (`... on line 91 of rollback.kes` for a built-in part) and exits 101. The line is the `fail` call's own (Kestrel keeps no call chain at run time). It is allowed in `pure` functions and `par for` bodies, which can already stop on an index out of range. Lowering: a new `kir` statement `FailWith { message, line }` that calls `kestrel_rt_fail(msg, line, file) -> !` and ends its block as `Return` does, so range analysis learns from `if me != 1 and me != 2 { fail(...) }` what it learns from `if ... { return }`.
3. **`exit`** flushes printed output, finishes a recording (decision 5) and ends the process with the code; nothing else runs (no drops, no `KESTREL_ARENA_REPORT`), as Rust's `process::exit`. A code outside 0 to 255 is a failure: "`exit` takes a code from 0 to 255, found 300 on line 4" (exit 101). It is an effect, like `print`: in a written `pure` function "pure functions can't call `exit`; return a value and let the caller decide", in a `par for` body "`par for` bodies can't call `exit`: iterations run at the same time", and a function that calls it is never inferred pure (decision 25). Lowering: `kir` `Exit(Expr)` calling `kestrel_rt_exit(code: i32) -> !`, ending its block. The Godot add-on sets a new `panic::set_exit_hook` that ends the run as returning from `main` does and logs `the program called exit(3)` for a code other than 0.
4. **Contracts.** `fail` breaks `no_panic`: "`half` can't be proven `no_panic`: it calls `fail` (line 3)"; `--report` lists it as a way to fail ("calls `fail`"). The allocations of `fail`'s own argument (an interpolated message) happen only on the way out, so `no_alloc` doesn't count them; every other allocation still counts. `exit` breaks no contract. `deterministic` holds through both: what they do depends only on their arguments.
5. **Exit codes in replays and the hosts.** The replay format goes to version 2 (`runtime/src/replay_file.rs`): the output log gains entry kind 3, `Exit(code)`, written last when the program called `exit` (a normal end writes none and means 0; a failure stays kind 2); version 1 files still read. `kestrel run --record` writes the file inside `exit` and the process ends with the program's code. `kestrel replay` compares endings too: a different code or kind is `replay differs at the end: the recording exited with code 0, this run with 1` (or "failed"), exit 1; a match stays `replay matches (N frames, M lines)`, exit 0, whatever code both runs ended with. `kestrel run` and a built exe end with the code. The reloading host: `exit` in `setup` or `frame` ends the session with that code (`frame` giving false is still the normal end, code 0), and `fail` ends it as a runtime failure does today.
6. **What changes.** `new_session` refuses instead of clamping: `if me != 1 and me != 2 { fail(...) }` with "`new_session` takes `me: 1` or `me: 2`, found 7", and `if delay < 0 or delay > MAX_DELAY { fail(...) }` with "`new_session` takes a `delay` from 0 to 8 frames, found 20"; the module comment and the syntax spec drop the clamping sentences (follow-up 83 closes). `rollback_delay.kes` loses its `clamped:` line. Pong's replay check (`kestrel run pong.kes run.replay`) exits 1 when the replay differs and 2 when the file can't be read or isn't a Pong replay, as `kestrel replay` does (follow-up 58 closes); its printed lines stay.

### B. `Result[T, E]`, `try` and `else why` (tasks 3-6)

7. **The type.** `Result` is a generic enum written in Kestrel in an embedded prelude, `kestrel/driver/std/prelude.kes`, which every file (built-in modules too) sees without a `use` and no `use` can name; diagnostics call it `<builtin>/prelude.kes`. It is `pub enum Result[T, E] { Ok { value: T }  Err { error: E } }` (one variant a line) with no methods this round. `Result` is a reserved type name: a struct, enum, interface or placeholder named `Result` is "`Result` is a built-in type; pick another name"; `Ok` and `Err` aren't reserved, since variants are always written `Result.Ok(...)` or bare inside a `match`. Everything generic enums have works unchanged: `Result.Ok(value: x)`, `Result[int, string].Err(error: "x")`, types worked out from the values and then the expected type, `match r { Ok o { o.value } Err e { e.error } }`, fields, lists and map values, `Result[T, E]` in generic code, `print` (`Result[int, string].Ok(value: 3)`), `checksum`, `to_bytes`, `from_bytes[Result[int, string]]`, `first_difference` (`r: Ok and Err`), interface method results, and a hot-reload state field (its shape description is the instance's, so a same-shape reload keeps it). Layout is the compiler spec's enum: a `u8` tag and a union (`Result[int, string]` is 24 bytes). **Departs:** the generics rule "an optional can't be `T`" is lifted for `Result` alone (its declaration never writes `T?`), because `from_bytes[int?]` exists and gives `Result[int?, string]` (decision 13); owning types and function types stay refused as `T` and `E` ("`World` owns an `Arena`, so it can't be `T` yet").
8. **A `T` goes in as `Ok`.** Where a `Result[T, E]` is expected (an annotated `let`, an argument, a field, a `return`, a function's or block's last expression, an `if` or `match` branch, a list item) a value that converts to `T` is wrapped as `Result.Ok(value: v)`, exactly where a `T` would go into a `T?` (recorded in `coerce`). An `Err` is always written. A value of type `E` there is "this is a `string`, the error type of `Result[int, string]`; write `Result.Err(error: ...)` for an error"; when `T` and `E` are one type nothing converts: "`Result[string, string]` has one type for its value and its error; write `Result.Ok(value: ...)` or `Result.Err(error: ...)`".
9. **`try`.** A new keyword and a prefix operator at unary precedence: `unary := ('-' | 'not' | '~' | 'try') unary | postfix`, so `try file.read(p)` applies to the call and `try f(x) + 1` is `(try f(x)) + 1`. On `r: Result[T, E]` in a function or closure whose result is `Result[U, E]` with the same `E`, `try r` is the `Ok` value (a `T`); on `Err` it returns `Result.Err(error: e)` from the function, moving the error (nothing copied or allocated). On `o: T?` in a function whose result is `U?`, it is the value or returns `none`. As a statement it drops the `Ok` value and is not a no-effect line (`try file.write(p, b)`). `try` is a `return`: it leaves `arena { }` and `in` blocks and drops what `return` drops, and the escape check applies to the error. Refusals, at the `try`:
   - the function returns nothing: "`try` returns the error from `main`, which returns nothing; handle it here, like `let x = r else why { print(why); return }`";
   - another error type: "`try` passes the error up, but this error is an `int` and `load` returns `Result[Save, string]`; handle it with `match` or `let ... else why { }`";
   - an optional in a `Result` function: "`try` on an optional needs a function that returns an optional; write `let x = opt else { return Result.Err(error: "...") }`"; a `Result` in an optional function: "`try` on a `Result` needs a function that returns a `Result`; write `let x = r else { return none }`";
   - anything else: "`try` takes a `Result` or an optional, found int";
   - a `par for` body: "`try` can't leave a `par for` body; handle the error with `let ... else why { }`";
   - a closure with no written or expected result type: "write the closure's result type, like `-> Result[int, string]`, to use `try` in it";
   - a constant or a field default: "`try` goes inside a function";
   - an error made in the `arena { }` it would leave: "`try` would return this error out of the `arena { }` block that made it, which frees it; handle it inside the block with `let ... else why { }`".
   Lowering: a tag test on `r` (a place is read in place, a temporary goes to a local first); the `Err` branch builds the function's `Err` from the payload and returns; the `Ok` branch reads `value`. The `kir` equals a hand-written `match` with a `return`.
10. **`let x = r else why { }`.** `binding := IDENT (':' type)? '=' expr ('else' IDENT? block)?`. On a `Result[T, E]`, `x` is the `Ok` value and the block runs on `Err` with `why` bound to the error (a view of the payload, as a `match` binding is); without a name the error is dropped. The block must leave, as today. On an optional: "an optional has no error to name; write `else { ... }`". `why` follows the local-name rules (no shadowing).
11. **`pure`, contracts, `par for`, generics.** Nothing new: a `pure` function may make, match, `try` and return a `Result`; building an error string counts for `no_alloc` as any string does, `no_panic` is untouched (an `Err` is not a failure), `deterministic` holds. A `par for` body may use a `Result` but not `try`. In generic code `try` needs the same `E` (a placeholder matches only itself). `Result` is `equatable` when `T` and `E` are (decision 19).
12. **`file` gives `Result`s.** `std/file.kes` makes its natives private (`native read_raw(path: string) -> list[u8]?` and so on, `native last_error() -> string`; the `kestrel_file_*` symbols and the native ABI don't change) and wraps them in Kestrel: `read -> Result[list[u8], string]`, `read_text -> Result[string, string]`, `list_dir -> Result[list[string], string]`, and `write`, `write_text`, `make_dir`, `remove -> Result[bool, string]` (`true` on success, until Kestrel has a type for nothing); `exists -> bool` stays. The error is the sentence `file.error()` gives today ("could not open `save.bin`: the system cannot find the file specified"). `file.error()` goes. The wrappers are not pure (they call natives), and `@prove(deterministic)` names the native as today.
13. **`from_bytes[T](b) -> Result[T, string]`**, the error naming the reason (`at` is a byte offset from 0, `n` the byte count): "the bytes are too short to hold a saved value: 3 bytes, and the header alone is 13"; "the bytes aren't a saved value: they don't start with KESB"; "the bytes were saved in format 2, and this Kestrel reads format 1"; "the bytes hold another type, or another shape of `Save`: a field was added, removed, renamed or changed"; "the bytes end early, at byte 57 of 57"; "byte 40 should be 0 or 1"; "the variant number at byte 40 is past the end of its enum"; "the string at byte 40 isn't UTF-8 text"; "the length at byte 40 is more than the bytes left can hold"; "the map at byte 40 has a key twice"; "the value ends at byte 44, but there are 45 bytes". The read helpers in `kir/src/lower/bytes_read.rs` return a negative reason code instead of -1 and leave the offset in a local; `decode_fn` turns code, offset and length into the sentence with one runtime call on the failure path (`kestrel_rt_bytes_reason`, with `T`'s printed name as a constant). It still never panics and never allocates by a length the bytes claim.
14. **Programs that change.** The voxel engine: `save_world -> Result[bool, string]`, `load_world(var w, var p) -> Result[bool, string]` with `let bytes = file.read(SAVE_FILE) else why { ... }` (a missing file gives "no world.save to load", another error "could not load: <why>") and `let save = from_bytes[Save](bytes) else why { return Result.Err(error: "could not load world.save: {why}; press F5 to save the world again") }`; `load_failure` goes and `main.kes` prints the error. Pong's `save_replay` and `check_file` print the `why`. Tests that declare their own `enum Result` rename it to `Outcome`: `tests/programs/generic_result.kes` (its line becomes `Outcome[int, string].Ok(value: 3) true`), `tests/errors/generic_written.kes`, `generic_infer.kes`, and the sources in `check/tests/generics_{written,bodies,infer}.rs` and `cli/tests/modules_generics.rs` (the parser-only tests may keep the name). The `from_bytes_*.kes` tests, `cli/tests/file_module.rs`, `from_bytes_reference.rs`, `kir/tests/bytes_read.rs`, `driver/tests/builtin.rs`, `bench/io/*.kes` and `voxel/tests/save_then_load.kes` print reasons where they printed `none`.

### C. Interface placeholders and `equatable` structs (tasks 7-10)

15. **Syntax.** `[pub] interface Name[P, Q: rule] { sig+ }` takes the generics' placeholder list. An interface instance is written with its types wherever an interface goes: interface lists (`struct Game: Rollback[Pad]`, `rollback.Rollback[Pad]`), rules (`[G: Rollback[I], I: equatable]`) and every type position (`list[Handler[Click]]`). Grammar: `interface := 'interface' IDENT tparams? '{' sig+ '}'`; `impls := ':' iref (',' iref)*`; `rule := iref | 'equatable' | 'ordered' | 'key'`; `iref := IDENT ('.' IDENT)* ('[' type (',' type)* ']')?`. The AST's `(String, Span)` interface lists and rules become references with type arguments. `interface Named<T>` gets the angle-bracket message structs get. A bare generic interface is "`Rollback` needs its types, like `Rollback[Pad]`". Interface methods have no placeholders of their own: "interface methods can't have placeholders of their own; put the placeholder on the interface, like `interface Handler[E]`" (a method table holds one function per method; Rust refuses generic methods on `dyn` traits for the same reason). Struct and enum methods' own placeholders stay refused.
16. **Instances.** `Rollback[Pad]` is an `IfaceId` made the way `Stack[int]` is a `StructId`: `IfaceInfo` gains `params` and `instance`, interned by declaration and types, with the declaration's abstract methods substituted. So `implements` keeps comparing ids and `kir`'s method tables stay keyed by type and `IfaceId`, one per instance. **Departs:** a struct or enum lists at most one instance of each interface ("`Button` lists `Handler[Click]` and `Handler[Key]`; a type implements one instance of an interface"), since Kestrel has no overloading and the two `handle` methods would share a name; the proposal's "two instances" inference error goes with it. Conformance is checked per listed instance, and its message writes the instance's types ("it should be `pure step(var self, one: Pad, two: Pad)`"). An instance is a value type as every interface is (two words; borrowed, boxed and copied as today). The generics' "which types can be `T`" rules apply to an instance's types, and the endless-copies check follows instances (`interface Grow[T] { more(self) -> Grow[list[T]] }` is refused at the declaration).
17. **Rules with types.** In `[G: Rollback[I], I: equatable]` the rule is the instance `Rollback[I]`, `I` a placeholder of the same list (before or after it); `g.step(a, b)` in the body is checked against `step(var self, one: I, two: I)`. A rule's types may be concrete (`[H: Handler[Click]]`). Two instances of one interface on one placeholder: "`G` can't have both `Rollback[Pad]` and `Rollback[I]`; keep one".
18. **Working a placeholder out from an interface list.** A new step between the values and the expected type (generics, "Working out the types"): a placeholder still open that appears in another placeholder's rule `R[..]` is read from that placeholder's type: `G` is `Game`, `Game` lists `Rollback[Pad]`, so `I` is `Pad` (an interface type `Rollback[Pad]` as `G` gives `Pad` too). Already decided otherwise: "`G` is `Game`, which implements `Rollback[Pad]`, so `I` is `Pad`, not `Input` (from `idle`)". A type that doesn't list the interface keeps today's "`Thing` isn't `rollback.Rollback`, so it can't be `G` in `rollback.new_session`".
19. **`equatable` covers plain structs and enums.** A struct is equatable when its fields are, an enum when its variants' fields are (bare variants always are), recursively; numbers, `bool`, `string` and vectors are as before; lists, arrays, maps, optionals, interface and function values aren't. `==` and `!=` then work on them everywhere: fields in declaration order, an enum's tag first (other variants are unequal), floats as `==` compares them (a NaN field makes two values unequal; `-0.0 == 0.0`); `xs.has(x)` and `xs.find(x)` work on lists of them. A generic instance is judged with its types (`Pair[int, string]` is, `Pair[int, list[int]]` isn't), `Result` too. Refusals: "`==` can't compare `World`s: its field `chunks` is a list; compare the fields you mean", and in a rule "`World` isn't `equatable` (numbers, bools, strings, vectors, and structs and enums of them are), so it can't be `T` in `count`". Lowering: a struct of scalars compares inline; other types call one generated `__kestrel_eq_N` per type (as `checksum`'s helpers are made), inlinable, `pure`, with no checks and no allocation.
20. **The rollback library takes the game's input.** `pub interface Rollback[I] { pure step(var self, one: I, two: I) }`, `Session[G: Rollback[I], I: equatable]`, `Packet[I]` (its `inputs` a `list[I]`, the same bytes as `[I]`), `Replay[G: Rollback[I], I: equatable]`, `FakeNet[I]`. **Departs:** `new_session(start: G, me: int, delay: int, idle: I) -> Session[G, I]` takes the input with nothing held, because generic code can't make an `I` (`I()` and `array[I](n)` are refused); the library fills its histories with `idle`. Guesses are compared with `==` (`same` goes; a NaN axis still never matches, `-0.0` matches `0.0`). `Input` stays as a ready-made input for simple games (`Rollback[Input]`, `idle: Input()`). `new_replay(start)` works `I` out from `G`'s list. A field writes both types: `p1: Session[Game, Pad]`.
21. **Pong goes back to its own input.** `Game: Rollback[Pad]`, `Pad { up: bool = false, down: bool = false }` (2 bytes), `step(var self, one: Pad, two: Pad)`, `bot` gives a `Pad`, `UP`, `DOWN` and `held` go, `pong.kes` passes `idle: Pad()`. Its 600-frame headless output and its desync output stay byte for byte (`pong_expected*.txt`); the replay's inputs go from 24 to 4 bytes a frame, so `pong_demo.rs` checks `INPUTS_AT + 4 * f + 4 + 8 * (f / 60)` and flips player 1's `up` byte at `INPUTS_AT + 4 * 300` (`bytes[at] <= 1`). The rollback tests write `Rollback[Input]` and `Session[Tally, Input]` (or their own input) with unchanged expected lines.

### D. `pure` inferred (task 11)

22. **Every function with a body is inferred.** After all bodies are checked, one pass over the call graph decides each function's and method's purity: pure when its body has no effect (`print`, the global `randf` family, `exit`, a native that isn't `pure`, a call through a function value whose type isn't `pure`, a call through an interface or rule method not written `pure`) and everything it calls is pure; recursion starts pure and drops on an effect, repeated until nothing changes. A generic function is decided once, on its declaration, so all its copies agree. `FnInfo` gains `pure_written`; `is_pure` becomes the inferred answer for the rest of the compiler (`kir/src/lower/lines.rs` then stores the call line before fewer calls; nothing printed changes, since a pure function calls no native). Natives, interface methods and function types keep `pure` written: they have no body.
23. **A written `pure` is a checked promise.** Its errors stay where they are today, at the call inside the written-`pure` function, and now say why, with the chain contracts use: "pure functions can only call pure functions; `report` prints (line 4)", or "...; `mesh_chunk` calls `log_face` (mesher.kes:40), which prints (mesher.kes:41)", help "remove the effect, or remove `pure` from `noisy`". Direct effects keep today's messages ("pure functions can't call `print`").
24. **`par for`.** A body may call any pure function, written or inferred; otherwise, at the call: "a `par for` body can only call functions without effects; `mesh_chunk` calls `log_face` (mesher.kes:40), which prints (mesher.kes:41)", help "remove the effect, or write `pure` on `mesh_chunk` to see the error there". The rules for the loop's item are unchanged.
25. **Types keep written purity.** **Departs:** the proposal gave `let f = height` a `pure` type when `height` is inferred pure; types are fixed while bodies are checked, before purity is known. So a named function's value type is `pure` when it is written `pure`, or when the expected type is a `pure` function type (`xs.sort_by(score)`, `let f: pure (int) -> int = height`, a `pure` field or parameter), which then requires it inferred pure: "`score` is used as a `pure` function here, but it prints (line 9)". A closure literal is pure when its body has no effect and calls only written-`pure` functions, or, where a pure closure is required (a `pure` function, a `par for` body, an expected `pure` type, a `sort_by` key), functions inferred pure, checked after the pass with the same chain. Elsewhere it gets a non-`pure` type, as today.
26. **Interfaces.** A call through an interface or a rule is pure only when the interface method is written `pure`. An implementation of a `pure` method may be inferred pure; one that isn't, after the pass: "`Game.step` implements `rollback.Rollback.step`, which is `pure`, but `Game.step` prints (line 6); remove the effect" (today's "doesn't match" message stays for the other differences).
27. **An unused result.** "the result of pure function `sq` is unused, so this line does nothing" fires for inferred-pure functions too, but only those that return a value. **Departs:** a stub with no result and no effect stays legal as a statement; written-`pure` functions keep today's rule.
28. **The rest.** `@prove(deterministic)` holds for every pure function, written or inferred. Hot reload, replays and `to_bytes` see nothing new. The LSP's hover says `pure (inferred)`. The demos keep their written `pure`.
29. **Tests that change.** `tests/errors/par_for.kes` loses error 22 (`tick` only changes its `var` item, so it is inferred pure); tests whose callee has an effect keep their line with the new text (`purity.kes`, `closure_types.kes`, `generic_bodies.kes`, `iface_use.kes`, `list_fns.kes`, `list_sort.kes`, and `check/tests/{check,structs,natives,closures,list_fns,list_sort,fn_values}.rs`); a test whose callee has no effect gets a `print` in it so it still tests the rule; `rollback_step_not_pure.kes` prints in `step` and gets decision 26's message.

### E. Packages (syntax and lock only)

30. **Declaring.** `use NAME from "SOURCE" vX.Y.Z` for a git repository, `use NAME from "PATH"` for a folder (relative to the declaring file, or absolute; `.`, `..` and drive letters mark a path). Any file of the program may declare a package, once; elsewhere `use NAME`, `use NAME.module` and `use { X from NAME.module }` use it. The package's own file is `<last segment of the source, without .git>.kes` at its root; its modules are found below it with the folder rules. The version is a tag `vX.Y.Z`, lexed as one token (`v` and three dot-separated numbers is never valid code otherwise) and required on a git source: "`netcode` comes from a git repository, so it needs a version, like `v0.3.0`"; "a path package has no version; remove `v0.3.0`"; a second declaration: "`netcode` is declared as v0.3.0 in main.kes and v0.4.0 in net/wire.kes; keep one". **Departs:** tags only, no `rev` (the lock pins the commit); `from` is the keyword (it is one already).
31. **`kestrel.lock`**, beside the entry file, written by the first `run` or `build` that fetches and by `kestrel update`, never otherwise changed. Text, one package a line, sorted by name, every package the program reaches (one copy each): `kestrel-lock 1` on the first line, then `netcode https://github.com/someone/netcode v0.3.0 <40-hex commit> sha256:<64 hex>` or `shared ../shared` (a path package has no commit or hash). The hash is SHA-256 over the package's files except `.git`, sorted bytewise by their `/` path, each as its path, a zero byte, its length as 8 bytes little-endian and its bytes. Text, not TOML, because the ruling dropped the manifest and a line format needs no parser. **Departs** in form only.
32. **The rest as ruled:** one copy per package, the highest `vX.Y.Z` with the same `X` when two ask (different `X` names both requirers); the cache `%LOCALAPPDATA%\kestrel\packages\<name>-<commit>\`; a name found as a folder and a package is an error; a package's `use` sees only its own files and dependencies; the exe and the replay header record each package's name and commit; a package's `pub` function counts as pure to its users only when written `pure`.
33. **Built in its own round.** This round's plan has twelve tasks, so packages (a `kestrel-pkg` crate with SHA-256 and `git`, `driver/src/load.rs`, `kestrel update`, the replay header) get their own spec check and plan.

### The grammar, every change

```
unary     := ('-' | 'not' | '~' | 'try') unary | postfix          // 9: `try` is a keyword
binding   := IDENT (':' type)? '=' expr ('else' IDENT? block)?    // 10: `else why`
interface := 'interface' IDENT tparams? '{' sig+ '}'               // 15
impls     := ':' iref (',' iref)*                                  // 15
tparam    := IDENT (':' rule ('+' rule)*)?
rule      := iref | 'equatable' | 'ordered' | 'key'
iref      := IDENT ('.' IDENT)* ('[' type (',' type)* ']')?
use       := ... | 'use' IDENT 'from' STRING VERSION?              // 30, parsed in the packages round
```

`exit`, `fail` and `Result` are reserved names, not keywords: they parse as calls and types.

### How the features meet the rest

| | `exit` / `fail` | `Result`, `try`, `else why` | interface placeholders | inferred `pure` |
|---|---|---|---|---|
| `pure` | `exit` no; `fail` yes | yes | methods keep written `pure` | decision 22 |
| `@prove` | `fail` breaks `no_panic` | as any enum; `try` is a branch | per instance, as today | inferred holds `deterministic` |
| `par for` | `exit` no; `fail` yes | values yes, `try` no | calls through `pure` methods | calls inferred-pure functions |
| generics | nothing new | `Result[T, E]` is one | rules take instances (17, 18) | decided per declaration |
| hot reload | `exit` ends the session | a `Result` field reloads in place | nothing new | nothing new |
| replays | exit code recorded (5) | nothing new | Pong's 4-byte inputs | nothing new |
| `to_bytes` | nothing new | an enum: `u32` variant, then fields | an instance's own shape | nothing new |

## Constraints

- One new keyword (`try`) and three reserved names (`exit`, `fail`, `Result`); the `else why` name and interface brackets are the only other syntax. No new Cargo dependencies. Files under about 400 lines. Every message a plain sentence that says what to do.
- Every existing program prints what it printed, in the JIT and both exes, except the lines decisions 6, 13, 14, 21 and 29 name. Pong's headless and desync outputs stay byte for byte.
- Never a visible window in tests. Builds at low load when the user is at the PC (the plan's Global Constraints).

## Measurements (release, quiet PC, median of five, in `kestrel/bench/kernels/results.md` and `bench/rollback/`)

- A `Result[int, string]` in a hot loop: `bench/kernels/result.kes` sums 10 million calls of a function returning `int`, `int?` and `Result[int, string]`, inlined and not (one too large to inline), and a three-deep `try` chain against the same written with `match`. Expected: `try` and the `match` give the same `kir` and machine code (a tag compare and a branch); a non-inlined `Result[int, string]` costs a 24-byte return slot against `int?`'s 8, a few cycles a call; a ratio over 1.2 against `int?` on the `Ok` path is a follow-up.
- `==` on `Pad` against two field compares: the same instructions.
- Pong's network frame on `Pad` against the rollback round's 6-9% (follow-up 96), and its replay size (4 input bytes a frame).
- `kestrel check` time on the voxel engine with the purity pass (target: under 2% more).
